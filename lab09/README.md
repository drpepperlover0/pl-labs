## ⚙️ Ответы на вопросы:

- **Какую ошибку выявляет таблица 2×3:** Прямоугольная таблица с разным числом строк и столбцов сразу ловит код, который по ошибке считает матрицу квадратной или путает порядок индексов `[row][column]`. При обращении по неверной размерности легко получить `IndexError` либо посчитать суммы не по тем направлениям.

- **Почему нельзя повторять одну изменяемую строку:** Запись `[[0] * columns] * rows` тиражирует ссылки на один и тот же внутренний список, поэтому правка элемента в одной строке меняет сразу все строки с тем же индексом столбца. Чтобы строки были независимыми, каждую нужно создавать отдельно через генератор: `[[0] * columns for _ in range(rows)]`.

- **Чем копия внешнего списка отличается от копирования строк:** Вызов `matrix.copy()` создаёт новый внешний список, но внутренние списки остаются общими с оригиналом — изменение ячейки внутри строки затронет обе таблицы. Полную независимость даёт копирование каждой строки отдельно (`[row.copy() for row in matrix]`), что и позволяет `transform` вернуть новую матрицу без порчи входных данных.

- **Рекурсия и трассировка `factorial(3)`:** Рекурсивная функция опирается на базовый случай (`number == 0` возвращает `1`) и уменьшающий шаг `number * factorial(number - 1)`. Для `factorial(3)` цепочка вызовов идёт так: `factorial(3) -> factorial(2) -> factorial(1) -> factorial(0)`, а обратные возвраты значений идут в порядке `1` (из `0`), `1` (из `1`), `2` (из `2`), `6` (из `3`). Итеративный вариант на цикле даёт те же результаты для чисел $0\text{--}20$, а искусственно задирать лимит рекурсии не стоит, чтобы не скрыть ошибки бесконечных вызовов или `RecursionError`.
