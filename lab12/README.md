## 🎯 Назначение проекта

Консольная программа для ведения списка настольных игр. Позволяет добавлять игры с указанием количества участников и категории, искать их, отмечать проведёнными, удалять, просматривать статистику и сохранять данные в JSON-файл. Проект демонстрирует разделение логики, хранения данных и пользовательского интерфейса.

## 📂 Структура проекта

В проект входят следующие файлы:

1. `main.py` — консольное меню, обработка пользовательского ввода и вызовы функций из других модулей.
2. `logic.py` — бизнес-логика: валидация записей, добавление, поиск, изменение статуса, удаление и сбор статистики. Не содержит ввода/вывода.
3. `storage.py` — чтение и запись JSON-файлов (с автоматической валидацией при чтении).
4. `test_logic.py` — автоматические тесты для проверки функций модуля логики.
5. `test_storage.py` — автоматические тесты для проверки сохранения и чтения файлов (с использованием `TemporaryDirectory`).
6. `data.json` — файл с исходными данными (вымышленный набор).
7. `README.md` — описание проекта, инструкции по запуску и результаты проверок.

## 📄 Формат данных (`data.json`)

Файл `data.json` в кодировке UTF-8 содержит JSON-массив объектов. Каждая запись имеет строго следующие поля:

- `id` — положительное целое число, уникальное в пределах файла;
- `title` — непустая строка (название настольной игры);
- `category` — непустая строка (категория, например, «евро», «патигейм»);
- `amount` — целое число не меньше нуля (количество участников; строго `int`, не `bool`);
- `completed` — строго булево значение (`true` / `false`).

Дополнительные поля не запрещены, но программа их не обрабатывает.

### Пример исходного набора данных

```json
[
  {
    "id": 1,
    "title": "Бункер",
    "category": "командные",
    "amount": 6,
    "completed": true

  },
```

## ⚙️ Архитектурные решения и особенности

- **Разделение ответственности:** `main.py` отвечает только за интерфейс и ввод/вывод, `logic.py` — за обработку данных, `storage.py` — за файловые операции. Благодаря этому логику можно легко протестировать или перенести в GUI.
- **Строгая валидация:** В `logic.validate_records` используется `type(x) is int` и `type(x) is bool`, чтобы избежать коварной ошибки Python, где `bool` является подклассом `int` (`True == 1`).
- **Генерация ID:** Новый идентификатор вычисляется как `max(существующих) + 1`. Если список пуст, берется `1`. При удалении записи ID остальных **не меняются** (в соответствии с ТЗ).
- **Умный выход:** При выборе пункта «Выйти» программа предлагает сохранить данные. Если при сохранении возникает ошибка `OSError` (например, файл заблокирован), программа не завершается, а возвращает пользователя в меню, чтобы он мог попробовать снова.
- **Безопасное чтение:** Если при запуске файл `data.json` поврежден или содержит неверную структуру, программа выводит сообщение об ошибке и завершается, **не перезаписывая** исходный файл.
